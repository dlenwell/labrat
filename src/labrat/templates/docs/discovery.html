Configured sources

UniFi Network, Proxmox VE, Pi-hole, and OPNsense are the integrations so far. Administrators add and edit these connections in Settings → Integrations; LabRat writes them, credentials included, to the private local_config.toml; a whole-install export from Settings includes them. The collector picks up valid changes before its next full scan. An explicit Test connection checks read-only API access without saving changes or running discovery.

Everything else is switched on in Settings → Discovery, and service discovery is permission-based: Network scanning lists the only subnets LabRat may contact, and nothing outside them is probed, whatever UniFi reports. NUT discovery finds UPS servers there and reads them with list commands only; LabRat never logs in or sends commands to a UPS. MikroTik discovery listens passively for MNDP announcements without sending anything. Announcements do not cross routers, so the collector hears only MikroTiks on its own network segment; for others, run the standalone listener on their segment.

python -m labrat.collector --once
python -m labrat.collector --list

--once performs one cycle and exits. --list reads the stored cache without contacting controllers. Running the command without either switch polls repeatedly at the configured interval.

What each adapter reads

Proxmox records physical cluster nodes and physical Ethernet interfaces where the API exposes them, using its interface active flag as port link status. Duplicate-MAC aliases and interfaces Proxmox marks as not existing are excluded. UniFi records adopted physical network equipment and ports from its local Integration API. Explicit down state wins over a positive reported speed; negotiated speed is used as link evidence when the source does not provide explicit state. The packaged model-profile catalog supplies known connector layouts offline; unknown connector types remain unclassified. Virtual machines, containers, and generic MAC-learning tables remain outside physical discovery. Connected UniFi clients are collected separately from infrastructure.

OPNsense records the firewall as one device with its network cards as ports, and keeps its health: version, uptime, load, memory, disks, and per-card counters. OPNsense has no read-only API role, so the user behind its API key should hold only the privileges in OPNsense permissions below; LabRat sends GET requests to a fixed list of endpoints and keeps only the fields it shows. Alias contents, credentials, and blocklist entries are never kept, only names and counts.

Beyond equipment and ports, Proxmox also feeds the Cluster page: each node's load, memory, history, storage, drives with their SMART readings, ZFS pools, Ceph health and OSDs, services, certificates, and pending updates, plus its guests. While a node's screen is open, LabRat reloads that data every 30 seconds. UniFi feeds the Networks page with its networks, Wi-Fi, firewall zones and policies, devices, and clients. OPNsense feeds it too: its networks and VLANs with DHCP (dnsmasq or Kea), WAN gateways, firewall rules in evaluation order, interface groups as zones, WireGuard peers, services, CARP state, and its DNS blocklist, and its gateways, VPN peers, and CARP addresses can raise Observations watchlist conditions. Pi-hole, when added, adds its statistics to the DNS sinkholes on Networks. All of it is read-only.

OPNsense permissions

OPNsense has no read-only API role: a privilege grants a whole page, and a page's privilege covers its actions as well as its reads.

  1. Create a group (System → Access → Groups) with only the privileges below, and a user in it with a long random password you never use. Never give it Firmware, Backup, System: Settings, or User Manager.
  2. On that user, add an API key. The key and secret go in Settings → Integrations.
  3. Limit the web interface, and so the API, to the address LabRat collects from, with a firewall rule or the web interface's listen interfaces.

Required. Lobby: Dashboard (every user has it) gives the system information a poll cannot complete without: name, version, uptime, load, memory, and disks. System: Status lets Test connection check the key.

Optional, by what each lets LabRat show. A missing one shows its part as not available and changes nothing else. Those marked * also allow changes on that page, so leave them out unless you want that part.

MikroTik on another segment

When the collector cannot sit on the MikroTiks' segment (a Kubernetes pod, or a VM on another VLAN), run the standalone listener on a machine that can, and let it report over the API:

  1. In Settings → API tokens, create a token with the Submit MikroTik announcements permission, and copy it: it is shown once. That token can do nothing else.
  2. On a host on that segment with LabRat installed (from a checkout, or the container image), run: 
    LABRAT_API_TOKEN=labrat_… python -m labrat.collector.mndp_push --url https://labrat.example.lan
    --token-file reads the token from a file instead; --ca-file trusts a private certificate authority; --once reports once and exits.

It listens exactly as the collector does, sending no MNDP probes, and reports what it hears over HTTPS to POST /api/v1/machine/mndp (see the API reference).

Browse client devices

Discovery has two views: Infrastructure keeps the infrastructure map focused, while Clients lists wired and Wi-Fi endpoints reported by UniFi, and the devices an OPNsense firewall has seen. A router knows a device used an address, not where it is plugged in, so its clients are Seen by router (still in its ARP or NDP tables) or Lease only, never connected; a device both report is one row, with its switch or access point first. Search by name, address, or manufacturer. The toolbar toggles show or hide VMs and containers, Wi-Fi, wired clients, and devices seen only by a router (each toggle's tooltip gives its count), and can narrow the list to unplaced or not-connected clients. Click a column header to sort (Address does not sort, since a VM can list several); headers stay visible while scrolling. A VM with several network cards is one row. Known server interfaces are hidden by default; turn on Show server interfaces to reveal them. VMs and containers are not placed or added to inventory. Exact Proxmox guest MAC matches show VM or container icons and their hosting nodes when the API token has VM.Audit access on /vms. Device icons follow the controller's reported classification, and lamps distinguish current, stale, and unavailable observations.

Select a client to inspect its reported identity, network, radio, traffic, and connection evidence in the side drawer. You can explicitly add it to inventory without placing it, choose your own display name, or place it using the same area and position forms as other equipment. A scan cannot overwrite your name or move the device. Placed clients appear in area views; Wi-Fi associations remain separate from physical cables.

Administrators can open Open ports for a quick check of 34 common TCP ports. This requires a fresh client address, an enabled reporting connection, Network scanning switched on, and an address or CIDR explicitly allowed in Settings → Discovery. Discovered subnet and firewall information does not grant permission. The check sends no application payloads, does not check UDP or every port, and cannot identify services from an open port alone. Closed, filtered, and unreachable outcomes are not distinguished.

Physical server cables

LLDP neighbors are matched to Proxmox nodes and physical NICs when their identifiers resolve uniquely. When a physical NIC has a unique MAC address, a targeted UniFi client lookup can supply an inferred switch-to-NIC cable. Shared MACs, stale records, down ports, and conflicting links remain unresolved. Inferred links appear by default with their evidence in the device inspector.

NUT reports a server's address but not its network interfaces. When UniFi lists that exact address as a wired client, LabRat infers one "Wired NIC" on the server and a cable to the switch port UniFi reports. When UniFi lists it on Wi-Fi, LabRat shows an inferred Wi-Fi interface and its access point instead, never a cable. Either inference disappears when UniFi stops reporting the match, and stays put while UniFi cannot be read.

An optional SNMPv3 supplement can provide physical NIC MAC addresses and operational link state when Proxmox omits them. Switch it on in Settings → Discovery and name the permitted nodes there; only those hosts are queried. Client lookup failures retain earlier observations with their original timestamps.

Resolve an unidentified neighbor

A switch inspector lists unresolved neighbors with their reported switch port, chassis identifier, remote port, and announced addresses. Discovery's inspector links to Equipment view for matching. Open Match to server NIC, choose an existing server and its physical NIC, then save the identity match. Ports already assigned to another observed cable are protected from conflicting choices.

The match is saved with the inventory server and used when the neighbor is observed again. If that neighbor disappears, its observed cable disappears too. Use Remove neighbor match in the switch or server inspector to undo the decision.

Failure and freshness

Collector requests are GET-only with timeouts. A failed cycle records a sanitized error type. Device records remain available when temporarily absent. Successful complete port and link snapshots reconcile vanished ports, aliases, and links; offline Proxmox nodes retain their last known NIC list until the next complete online scan. Explicit port-down state overrides speed, so a nominal speed on a down UniFi port does not count as an active link.

Placement remains a human decision

Discovery observations do not automatically create canonical devices or set physical positions. When placing an unlinked observation in Discovery, choose whether to create a new inventory device (the default) or link it to an existing one. The existing-device path links records; it does not merge or delete inventory entries. Rack and area pages use saved inventory placements. Link candidates retain their confidence and evidence and do not become canonical cables automatically.
